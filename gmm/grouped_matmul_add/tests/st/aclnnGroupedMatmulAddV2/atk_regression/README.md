# ATK performance comparison

Run `run_atk_perf.sh` in a configured CANN environment with ATK, PyTorch and openpyxl installed. Pass the absolute vendor directories for the pre-change implementation, final implementation and fixed-eight-row implementation, an output directory, and an idle physical NPU id. The fixed-eight-row build supports the expanded paths; the pre-change build does not.

Set `ATK_PERF_PILOT=1` to run only case 0 as an end-to-end setup check. Clear it for the three-round run.

The script runs three alternating rounds of ATK `performance_device` for the legacy shared path, the same-type 16-bit output path and non-transposed FP32 output. It copies each `kernel_details.csv` before ATK removes its profiler directory. Its executor seeds the random generator and uses an exactly representable grid; it logs canonical hashes of the inputs. Repeated performance calls may mutate the in-place `y`, and ATK's warmup/reset policy is not known from its binary implementation. These numbers are kernel timings, not accuracy results. Run `python summarize_atk_perf.py OUTPUT_DIR` to validate per-case hashes, profiler event counts and means and write paired CSV results.

ATK may warn that the profiler stopped in the RECORD state. Verify the retained event count and mean against the per-case Excel output rather than treating the warning as a pass; the local probe captured 20 kernel events per case. The two compared vendors must use the same CANN, build options, dependencies and physical device. Record other host activity and do not treat overlapping timing intervals as proof of no regression.

For non-grid dual-benchmark checks use `executor_dual_random.py` with `legacy_fp16_dual.json` or `legacy_bf16_dual.json`, setting `GMM_ATK_INPUT_DTYPE` to `fp16` or `bf16` respectively. In an environment configured for the target vendor, run `atk aclnn CASE.json --task accuracy --compare-backend npu --compare-devices 0 --devices 0 --concurrency 1 --timeout 180 -p executor_dual_random.py -o OUTPUT_DIR`. Repeat with the other vendor on the same device and compare input hashes and the `Actual` and `Benchmark` error statistics in the reports.

To extend the original-path comparison from three to eight rounds, use the same output directory from the initial run: `bash run_atk_legacy_extra.sh BASE_VENDOR FINAL_VENDOR OUTPUT_DIR PHYSICAL_DEVICE`. Then run `python summarize_atk_legacy8.py OUTPUT_DIR`. The summaries reject failed ATK cases, missing or mismatched profiler events, input dtype/shape discrepancies and hash mismatches. Run `python check_summary_rejects_failure.py OUTPUT_DIR` to check that both summarizers reject injected failures without changing the original reports.

The performance runners launch ATK in the background to retain profiler files. If interrupted, check and stop any remaining processes started by that run before reusing the device. Input hashes are checked as per-run multisets, not mapped to individual case IDs.

The fixed-eight-row comparison package used in this run was built from the same operator source as kernel commit `40cb1253e`, with only `op_kernel/grouped_matmul_add.cpp` changed: set `LOW_ROWS` to 8, remove the adaptive `rowsPerChunk` choice, and use `LOW_ROWS` consistently for loop steps, tail rows and event conditions. Build it as a separate vendor with the same CANN, dependencies and Release options as the final package. The recorded configuration used CANN 9.3, ascend910b, opbase `8e8cf1b`, ops-tensor `c7798ac7`, and CMake settings `VENDOR_NAME=gmmadd40cb8row`, `ASCEND_OP_NAME=grouped_matmul_add`, and `ENABLE_TILING_SINK=OFF`. Keep the original and final source trees unmodified when creating this comparison package.
